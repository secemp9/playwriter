When the agent needs to understand **where things are on screen**, `screenshotWithAccessibilityLabels` returns a screenshot with a color-coded `[N]` label at the top-left corner of every visible element `observe()` lists. The agent looks at the screenshot, reads the labels, and acts on those refs.

## Basic usage

```js
await screenshotWithAccessibilityLabels({ page: state.page })
// The image and the observation text are included in the response automatically
```

The function observes the page, captures the viewport once with CDP, and draws the labels onto the image in Node. Nothing is added to the page: no overlay DOM and no injected script. The image is in CSS pixels, so image coordinates match page coordinates; it is downscaled to fit 1568 px when the viewport is larger. Both the **image** and the **observation text** are returned.

## Interacting with refs

The labels are the same numeric refs `observe()` prints, so `act.*` takes them directly:

```js
await screenshotWithAccessibilityLabels({ page: state.page })
// The screenshot shows [5] on the "Submit" button
await act.click(5)
```

## Color coding

Labels are **color-coded by element type** for quick visual parsing:

| Color | Element type |
|---|---|
| Yellow | Links |
| Orange | Buttons |
| Coral | Inputs |
| Pink | Checkboxes |
| Peach | Sliders |
| Salmon | Menus |
| Amber | Tabs |

## Multiple screenshots

You can take **multiple screenshots** in a single execution. All images are included in the response:

```js
await screenshotWithAccessibilityLabels({ page: state.page })
await state.page.click('button.next')
await screenshotWithAccessibilityLabels({ page: state.page })
// Both images are returned
```

## Options

| Parameter | Type | Default | Description |
|---|---|---|---|
| `page` | Page | required | Playwright page to screenshot |
| `scope` | number | none | Only label this ref and the elements inside it, like `observe({ scope })` |

The call refuses a background tab, because Chrome paints nothing for it, so there is no picture to take. `observe()` needs no pixels and still works. If you need a picture, ask the user to switch to the tab. The call also refuses a pinch-zoomed page, and an observation the page has navigated or scrolled away from. In that case, observe again.

## When to use

Use `screenshotWithAccessibilityLabels` for **complex visual layouts** where spatial position matters: grids, image galleries, maps, dashboards, canvas-based UIs.

For **text-heavy pages** (forms, articles, lists), prefer `observe()` or `find()`. They are faster, cheaper, and use fewer tokens.

Both use the **same refs**, so you can switch between text and visual modes freely.

## Resizing images

To reduce token usage, resize screenshots before reading them back into context:

```js
await state.page.screenshot({ path: '/tmp/page.png', scale: 'css' })
await resizeImageForAgent({ input: '/tmp/page.png' })
// Resized image is automatically included in the response
```

`resizeImageForAgent` accepts `width`, `height`, `maxDimension`, `quality`, and `format` options.
